# 独立成员快照协议验证

新增成本核实结果见 [COST_STUDY.md](COST_STUDY.md)：独立进程存活堆测量、
共享/复制成员数组比较，以及字典＋排序树在后台扫描竞争下的延迟。

这是控制台研究程序，不引用 Garnet/Tsavorite，不接入 CPR，不修改恢复格式。
只验证稳定遍历与旧分数交接；没有 SortedSet 的排序树、TTL、命令处理或持久化。
基于 `ckpt-cou` / `350fa9910d541f7d9f7cbb364be4f10c1eff4dbb`，main 未改动。

## 协议

`Owner.cs` 用 byte[] 内容字典查找实时成员，用双向节点链维护稳定槽。
节点有单调递增编号；节点不会因字典扩容移动。成员字节在新增时复制，之后不修改、不池化。
开始快照只记录编号上限、成员数和首节点，没有复制列表或字典。

同一个 gate 保护修改、旧分数捕获和批次游标推进。未扫描的边界节点首次修改才保存旧分数；
再次修改复用第一次旧值。扫描已经经过的节点不再捕获。每批只从上次游标继续。
删除未扫描边界节点时，实时字典移除成员，但链表保留节点。重插取得新编号，超过边界，
旧节点仍输出旧分数，新节点不输出。扫描复制不可变成员引用和分数到批次，然后解除 gate；
调用方可以在 gate 外编码。批次消费是快照旧值所有权的交接点。

扫描过的已删除节点立即 O(1) 脱链；快照外或边界后新节点删除也立即脱链。
没有无限累计 tombstone，也不重用编号；编号溢出会在新增前 checked 拒绝。
Finish/abort 使用同一 Close，分批排空旧视图并释放旧分数和保留节点，之后才允许新快照。
Close 总工作量可为 O(N)，但每次 gate 最多访问一批节点，期间允许更新。
失败/取消指调用方显式 Close 丢弃结果，不代表 CPR 的失败清理已解决。

只允许一个快照和一个扫描/关闭调用者；修改调用者可多线程。Read/Close 不能由多个消费者并行调用。
返回的 ReadOnlyMemory 只读契约不允许通过 interop 修改底层数组。

## 有界性

默认最多 2,000,000 个 live+retained 节点、128 MiB 已链接成员字节、单成员 4096 字节。
超出配额的新增在修改前拒绝；分数更新不增加动态旧值记录分配。
每节点预留一个旧分数字段，而非每次修改分配记录。代价因此发生在正常运行内存中。
默认批次最多 128 个节点、16 KiB 成员字节；参数上限是 1024 节点、1 MiB。
返回批次引用可能延长脱链节点字节生命周期；驱动只保留一个扫描批次，外部调用者也必须如此。
字典容量会保留到历史最大 live 数；槽配额限制它的增长，但这不是 CLR 进程内存的硬字节上限。
列表/字典对象、分配器碎片和调用方保留的批次均不包含在 keyBytes 中。

## 可复现运行

无 NuGet 包依赖；本目录 NuGet.Config 清空远程源，Directory.Build.props 隔离仓库公共构建属性。
在仓库根目录：

```sh
/usr/local/share/dotnet/dotnet run --project research/checkpoint_cou/member_protocol/MemberProtocol.csproj -c Release -p:UseSharedCompilation=false -m:1
```

验证不需要 socket、服务器或 vstest。常规 dotnet restore 仅为本机框架生成 assets 文件。

只运行新增并发压力测试（跳过微基准）：

```sh
/usr/local/share/dotnet/dotnet run --project research/checkpoint_cou/member_protocol/MemberProtocol.csproj -c Release -- --stress-only
```

## 正确性结果

3 次独立进程运行均通过：

- 4 轮完整快照，对照边界的全部成员和分数，无重复；批读任务与修改任务以完成顺序控制交错。
- 扫描前/后更新、同成员反复更新、删除/插入/删除后重插、插入 10,000 个成员触发字典扩容。
- 部分扫描后丢弃结果并 Close，随后再次快照；每轮关闭后 Slots == Count。
- 输入数组后续修改、批次跨 Close 存活、空边界、同时第二快照拒绝、槽与字节配额拒绝。
- 100 个固定种子，每个 3 个 generation，每代 200 个修改/扫描步骤，对照完整参考模型。

这些测试的边界是 Owner.Begin 持有 gate 的时刻，这是独立协议的明确定义。
它不能外推为 Garnet BGSAVE 请求瞬间的全局切点。这里也没有证明任意机器调度交错或 CPR 恢复正确。

### 新增真实并发测试（2026-10-30）

上面的 Task.Run 顺序交错仍是顺序测试；新增 `ConcurrentStress.cs` 使用 4 个
LongRunning 写任务持续随机 Set/Remove，一个调用线程同时分批 Read/Close。
写线程在 Begin 前已经启动，Begin、批读与 Close 期间持续运行；只在每轮关闭后用 barrier
暂停写入，以便核对回收不变式。没有逐次等待写操作完成后才调用 Read。

Begin 的可选 `captureForTest` 钩子在同一个 gate 内复制实时字典的全部成员字节和分数，
形成该轮参考答案；默认 null 时不扫描或复制字典。这个 O(N) 测试钩子会阻塞写入，
不是协议优化的一部分，也不能用于 Begin 性能测量。钩子在 active 发布前调用，
抛出异常不会遗留活动视图。测试参考答案只在钩子中创建，之后不受写线程更新。

每轮核对每个输出成员存在于参考答案、分数相同、无重复，完整轮次还核对精确成员数。
每 10 轮模拟一次消费失败：丢弃部分输出并 Close，在写线程继续运行时排空旧视图。
回收检查在持锁且写线程静止时遍历链表，检查编号顺序、前后链接、live/index 对应、
无残留 HasOld、slots/count/keyBytes 一致；后续轮次继续 Begin。
这属于 owner 消费中止测试，不模拟 CPR 状态机或设备故障。

## 初步成本（本机，3 次进程运行）

原始输出在 `results/local_r1.txt` 至 `local_r3.txt`，含测试状态和 CSV。
这些是新增并发测试和 Begin 测试钩子之前的历史微基准；本轮没有更新其性能结论。
10 万成员、每组 20 万次 Set，先更新后扫描，模拟未扫描成员的保护成本。
下表为中位数；这是短时、无竞争微基准，没有编码、网络、磁盘、排序树或 CPR。

| 指标 | 结果 |
| --- | --- |
| 初始化分配量：相对仅内容字典每成员额外分配 | 72.00 字节 |
| 同内容比较器、私有成员副本、简单 monitor 字典更新 | 44.81 ns/op |
| Owner 无快照 Set | 80.49 ns/op |
| Owner 快照 Set，1% / 80% 成员覆盖 | 91.06 / 91.97 ns/op |
| 首次旧分数赋值段，1% / 80% 覆盖 | 10.22 / 9.92 ns/capture |
| Set gate 持有，1% / 80% 覆盖 | 60.98 / 61.92 ns/op |
| Set gate 获取，1% / 80% 覆盖 | 13.83 / 13.97 ns/op |
| 批读，1% / 80% 覆盖 | 6.47 / 6.00 ns/member |

Gate/capture 计时本身带 Stopwatch 开销；字典基线没有这些额外计时，不能把差值全部归因于协议。
gate 获取是无竞争调用开销，不能解释成竞争等待性能；未测 Remove/Read 的 gate 时长。
1K 组用于热身，不作为性能结论。不同数据规模的比较尚不足以证明渐近复杂度或吞吐增长。

原始输出也包含强制 GC 前后 heap 差值；10 万成员显示额外约 144 字节/成员，
但小规模样本波动大，且 heap 差值与线程分配计数并不一致。此值只保留为诊断，
不能作为精确 retained-size 或进程峰值内存结论。初始化分配量也不等于存活内存。
因此目前可以确认存在明显正常运行开销，尚不能认定成本可接受。

下一步应使用隔离进程/堆分析核实节点、字典容量、成员副本和批次的实际存活成本，
增加多成员长度、对象规模、读写竞争、暂停扫描期间删除/重插的测量。
之后才决定是否处理 Garnet 的 CPR 边界、CAS 前拒绝接口和失败生命周期；本轮不接入服务器。
